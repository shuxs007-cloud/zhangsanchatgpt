# 导出状态通道超时修复（2026-09-25）

## 本次确认的事实

失败运行 `20260925T010054+0800` 已取得导出任务ID，随后状态GET的CDP `Runtime.evaluate` 连续3次在约60005/60007/60006毫秒未返回。日志分类原为read_timeout，最终错误为CDP command timeout；没有HTTP429回执。本证据不能区分服务器未响应、页面执行停滞或CDP异步返回异常，不能声称已经查明更底层原因。

旧代码通过长awaitPromise等待整个页面fetch，页面内AbortSignal期限未产生可收到的结束结果；外层60秒超时只删除CDP待处理项，并不取消页面HTTP请求。白名单重试未核对旧请求结束。生成状态失败也未更新导出断点，最终JSON只显示submitted和退出码。

## 修复边界

- 仅导出状态GET使用本机45秒期限、同步短CDP指令检查的同页内存请求槽。每次尝试只发一个同taskId HTTP请求；每秒读取内存结果不是增加HTTP轮询。状态轮询仍15秒，下载前仍至少60秒。
- 请求/响应体超时后显式取消并确认收尾，才按原冷却及重试上限查询同taskId。不重新生成，不访问可见页面，不改变认证、AES或后台业务。
- 若CDP结果未返回但相同请求的完整HTTP响应已保存在本次内存槽，直接消费这份结果，不重发请求；HTTP401/429和Retry-After保持原语义。未取得完整响应不猜测。
- 页面真正无响应且无法确认收尾时禁止下一请求：保留原队列锁和blocked.json，等待处理，不自动抢锁。该保护可能中止本轮，而不是保证任何服务器/浏览器异常都能恢复。
- 分类区分browser_runtime_timeout与已确认请求结束的read_timeout；旧未确认CDP超时不盲目重试。业务POST不重试。
- 成功状态持续写断点；失败保存generationFailure供runner/最终JSON/MD使用，不泄露凭据、响应正文和请求体。成功回执的轮询周期元数据纠正为实际15000毫秒。
