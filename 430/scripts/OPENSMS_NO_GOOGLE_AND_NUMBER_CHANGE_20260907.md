# 任务A取消Google依赖与换号状态说明

## 用户要求与适用范围

2026-09-07：任务A不再下载或使用Google文档。范围包括定时A-only，以及手动完整巡检的基础报表阶段。新鲜系统导出、服务器日期核验、身份校验、正常运营商规则、独立回读与三份主要交付保留。此次开发不授权执行任何后台业务。

Chatr截止日由系统导出提供；其激活日期如系统有则保留，无则允许空白、不再补查。Kooda激活日期和截止日仍逐字段系统优先，缺字段才用本轮生成前冻结的本地F库，不覆盖系统值。A-only不联网执行F，手动普通巡检的后台F规则不变。

## 换号状态怎样生成

实现函数：`services/opensms_document_api/pipeline/process_card_slots.py` 中 `classify_number_change`，独立复核程序另行核算。输入创建时间来自本轮源表的“创建时间”列；这是推算字段，不是后台换号动作或历史记录的直接回执。

| 顺序 | 条件 | 输出 |
|---|---|---|
| 1 | Kooda激活日期与截止日都缺失 | 未换号（按现有新卡假设） |
| 2 | 其它情况缺创建时间或有效参考日期 | 空白，无法判断 |
| 3 | 创建时间与参考日期的绝对时间差严格大于72小时 | 已换号 |
| 4 | 差值小于或等于72小时 | 空白，并非显式“未换号” |

旧参考日期优先激活日期，没有则使用Google上卡日期；取消Google后没有上卡日期回退，只用解析后的有效激活日期。比较的是完整时间差的绝对值，不是只比较日期文字，也不是“创建时间一定晚于激活日期”。例如相差恰好3天不标记，超过3天才标记。

Chatr无激活日期时留空，不从截止日减29天推算，也不因截止日存在就宣称已激活。Kooda仅缺一个日期时不适用“双日期空白新卡”例外。

### 与任务C的关系

`scripts/opensms_generate_task_c_candidates.py` 的现有 Chatr 规则把空白与“未换号”都视为可继续判断的状态，再检查发送量、4日回复率、到期优先级与保护区等条件。取消Google会使部分Chatr行失去换号判定依据，但本次没有改变任务C的业务条件。空白不代表事实确认未换号；如需改变该处理方式，需用户另行指定规则。任务C仍默认关闭，只接受当轮明确授权。

| 原用途 | 停用后处理 |
|---|---|
| 按归一化卡槽关联二、三、四号机房记录 | 不再进行Google关联；系统身份核验保留 |
| 给Chatr及其它非Kooda补激活日期、预计过期日 | 不再补；系统字段优先，缺失明确留空 |
| 提供上卡日期 | 不再获取；开卡日期留空 |
| 上卡日期作为换号/激活判断的次级参考 | 取消回退，不倒推日期 |
| 提供Google电信商/价格，与OPR比较告警 | 去掉专属列及“电信商_OPR预警”工作表 |
| 列出系统卡槽未匹配Google的情况 | 不再生成“未匹配卡槽”工作表 |
| “所有谷歌有-系统没有”全量差集 | 停止生成，不输出伪空表 |
| “谷歌文档中有激活日期-系统无法使用”及关联整行标黄 | 停止生成；不声称已完成Google对账 |
| 给差异表提供备注、ICCID、手机号、上卡日期、电信商、页签及行号 | 对应Google差异明细和专属来源列取消 |
| 补充系统完全未出现的设备到64端口统计范围 | 未使用端口改为仅覆盖本轮系统源表中出现的设备 |
| 以激活日期/上卡日期筛“已激活未上架”及机器汇总 | 只保留有有效激活日期的记录，不能覆盖无激活日期的Chatr |

未使用端口仍逐设备展开1至64：系统无该端口记录显示“系统中无”；端口记录全部注册失败显示“注册失败”；任一记录不是注册失败则不列为未使用。**整台设备都不在本轮系统源表中时，无法发现其64个端口，不能再声称覆盖所有设备。** 机房归属的现有卡槽/设备映射规则不依赖Google，保持不变。

## 程序与安全约束

- 正常runner固定Google关闭，不派发Google下载，也不复用旧文件或创建假的Google输入。
- 文档入口支持`--no-google`，关联表不是必需输入；运行强制本地生成，不能误调依赖Google的旧局域网接口。

- 独立回读重新核验日期来源、换号状态、64端口范围、ICCID、红色标记及Google专属表/列不存在。停用项明确标记skipped，不冒充执行成功。
- 有依赖的运营商写入、回读和文档刷新保持顺序；B/C/D/E授权和F门禁不变。历史交付不修改，不把离线测试表当成新鲜导出交付。
