## 使用

**完整流程已统一，今后优先用 `run`，不再依赖上一批182个ICCID的临时程序。**

```bash
bash scripts/run_opensms_task_i.sh run --list /绝对路径/号码清单.txt --workers 7
```

一条命令依次完成：搜索本地表格文件、跳过未变化文件、7路解析新增内容入索引、7路查询及历史去重、并行独立原表抽查、生成六页Excel、保存后独立回读全部号码及六项指标。每次自动建新的任务I报告目录，不覆盖上次文件。既支持ICCID也支持手机号，允许多个 `--list` 自动分批，或 `run 8912230200278094459 14389392694 --workers 7`。

运行回执 `run_receipt.json` 包含每个环节和全流程耗时、实际工作进程PID、线程优先级结果、覆盖/未索引状态及核验结果。任一环节失败即记录断点，不自动重跑。默认全程离线，最新位置显示“未实时查询”，历史最后位置仍单列；不启动以前的在线位置查询。当前另行授权取得的新鲜搜索导出，可用 `--current-search-receipt` 独立核验后附加。

查询直接走数据库，不扫描所有文档。刷新只打开新增或大小/修改时间变化的文件。首轮索引完成后再次刷新，未变化的文档跳过。每次查询结果附索引更新时间；需要当前所有文件时先刷新再查询。

## 精度与统计

1. ICCID仅使用可靠文本，允许去空格和末尾一个F/f。数值型/公式型ICCID不猜补精度。
2. 加拿大/美国手机号统一去国家码1，以末10位作查询键；其他不合法格式不猜测。
3. 逐日指标只读取原表明确的发送窗口数、回复窗口数、总发送量、总回复量，不加总滚动10日合计。
4. 相同查询身份、手机号、平台日期只保留一个版本。已结束平台日期优先于当日未结束快照，再选最新可确定采集时间。最高优先级冲突时排除并标记待核对。存在已结束日数值变化时保留冲突版本和采用来源。
5. 每卡总回复率为回复窗口数合计/发送窗口数合计。总回复数按短信回复条数处理，与总回复量是同一项，不重复计量。短信量回复比另列，不能代替窗口回复率。
6. 原表未有完整年月日的MM-DD依据确定的文件/归档年补年并处理跨年，修改时间不是确定采集时间，其指标不能进入历史总计。
7. 无记录、缺失指标、无法读取与真实0区分。统计是已保存、可读取且可精确匹配的历史，不保证卡的完整生命周期。只按同条记录ICCID匹配，不通过现在的手机号倒推另一张卡的旧流量。
8. 混合ICCID/手机号批量查询若出现同一流量交叉，禁用组合总计，避免重复累计。

## 索引一致性

一个协调器写库，默认7个、最多8个CPU读取进程。专用锁阻止重复建库。事务提交后断点可再次增量刷新，不执行业务重试。OOXML首轮内容分组采用ZIP成员CRC32/大小清单哈希（不是原文件字节SHA256），工作表XML和共享字符串另用SHA256索引；文档原路径均保留。

日常刷新执行文档注册表完整性检查、新增记录校验与事务提交后核验，不再每次重检约7GiB全库；回执明确标注 `registry-and-new-records`，不冒充刚做完全库审计。全库审计仍可明确执行 `index --full-audit` 或 `run --full-audit`，首次建库必做全库检查。文件没有变化时保留同一索引版本。记录数和ICCID/手机号数量仍按索引实时精确统计，不拿旧计数充当前结果。

验证包括长ICCID文本精度、手机号规则、跨年、空值与0、同日多快照、文档数量、并行原文件独立抽查、Excel每个号码的六项计数/比例和历史/最新位置分列。同一短信日期的重复滚动表不会直接相加。批量列表里的同一规范化号码自动去重；ICCID和手机号交叉命中时停用组合总计，手机号视图同一流量仍只累计一次。

7路采用CPU多进程而非受Python全局解释器锁限制的7个普通线程，可由系统调度到7个CPU核心；macOS不提供此流程可用的固定核心绑定，不宣称固定占用指定核心。报表同一工作簿最后写出保持单路，防止并发写损坏。最高普通应用QoS不等于实时调度，nice权限不足如实记载。
