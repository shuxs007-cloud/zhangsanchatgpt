# 任务D保留卡区结果统计

2026-09-07新增输出。完整业务规则仍以 `OPENSMS_10DAY_PATROL_POLICY.md` 为准；本文说明程序实现和验证，不是一次实际任务D的执行回执。

## 用户看到的结果

任务D完成时，聊天摘要直接显示“本轮新转入保留卡区 X 个；执行后保留区共 Y 个”。完整报告按“B14-C快下保留卡”“B14-T快下保留卡”和合计列出两项数量及统计时间。

- 新转入：本轮真实写前来源在两个保留区之外、已成功修改并独立回读、且结束时全量回读仍确认在目标保留区的唯一手机号。
- 已在保留区无需修改、两保留区之间互转、候选但未写入、失败或未确认的号码不计新增。
- 区内总数：任务D全部业务完成后，从号码管理按两个精确运营商分别读取全部分页，以规范手机号去重。不是卡保留申请日志数，也不是候选数或本轮工作簿行数。
- 0个新增但仍有存量会显示真实非零总数；未执行或统计失败不能把未知显示为0。后续E失败不隐藏已完成D的有效统计。

## 程序链与证据

原D业务按原顺序完成 → 两保留区后台全量只读回读 → 本地证据核算 → D完成 → 文档刷新 → 后续授权步骤。

- `opensms_collect_task_d_retention_population.mjs`：每页500，最多4个只读并发；保留精确运营商、分页total/行数、逐号后台ID及静默证明。重复后台ID、跨区重复号码或不完整分页均拒绝。
- `opensms_task_d_retention_summary.py`：不联网，核验本轮候选、写前后台来源、真实写入回执、独立验证与结束快照，逐号核算新增及存量并固定各证据SHA-256。
- `opensms_patrol_runner.py`：只有本轮授权D且所有D业务完成后才派发统计；最终JSON保留 `taskD.retentionSummary`。统计失败保留业务断点，不自动重复写入。
- `opensms_parallel_audit.py`：独立重新核算统计和哈希；新统计缺证据时不可交付为完成。
- 聊天仍维持固定七节和三个主要文件链接；完整MD保存分组表、时间及详细回执链接。各原任务授权、写入保护和业务顺序不变。

本轮完整明细随正常交付归档到对应runId的receipts目录，不覆盖历史。新增统计读取只在获授权D完成后发生，定时任务A不会因此查询或执行D。
