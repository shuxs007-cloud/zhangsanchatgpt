# 430静默页面修复

## 范围

修复共享 `opensms_protocol_client.mjs` 的临时页面创建和脚本执行，以及巡检API目标的跨进程生命周期。最初连接层验证没有执行任务A导出、登录提交、号码修改或BCDEF业务；后续完整验收单独记录在末节。上次完整运行置顶的确切事件没有OS级历史证据，不能倒推已经确认根因。

## 实测与修改

- 原实现仅 background:true，仍创建普通标签页；脚本还默认 userGesture:true。
- 现改为 hidden:true、background:true、forTab:false，无普通标签页降级；脚本 userGesture:false，禁止公共传输激活页面/标签或改变窗口。
- 当前430协议声明hidden支持，但显式newWindow:false导致“Hidden target cannot be created in a new window”。指定返回的browserContextId也不能可靠创建。省略这两个参数、保留hidden约束后创建成功。
- hidden页面寿命绑定创建CDP会话，因此API创建入口派生保活进程；等待创建回执后返回，保活进程保留连接。主runner消失或目标关闭后自动结束。
- 创建/读取/day/关闭测试前、中、后，前台进程ID均15242，页面hasFocus=false。仅证明该小范围测试没有观察到焦点变化，不代表所有完整流程实测完成。
- 跨进程测试确认创建入口退出后隐藏目标仍存活，独立关闭成功，保活进程随后退出。
- 18项离线回归通过：焦点命令禁止、用户手势关闭、hidden无降级、导航及登录预检。

下一轮只通过原入口运行；若隐藏页面能力失效则停止，不强行弹出窗口。历史浏览器置顶回执中的静默布尔值不能当作OS焦点证据。

修复为优先匹配本轮固定targetId，限定类型为`page`或`other`，继续强制验证OpenSMS同源和WebSocket连接。未固定ID的一般发现流程仍只查普通页面；不允许跨ID、跨来源、worker或可见页面降级。
